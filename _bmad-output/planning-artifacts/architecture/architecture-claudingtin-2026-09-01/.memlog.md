- (decision) Fork 1: paradigm = hub-and-spoke relay. Backend is the single authoritative in-memory hub for queue/pairing/session state; companions are near-stateless spokes (render+relay, never enforce); no spoke-to-spoke. Binds: all 3 v1 units. Prevents: divergent state ownership, p2p paths that bypass moderation, any client-side enforcement.
- (decision) Fork 1b: backend enforces ALL of identity check, cooldown, block, ban, rate limit, relay. Companion presents the UUID and renders only. Prevents: the open-source client becoming load-bearing for safety; two enforcement points drifting.
- (decision) Unit split (ADOPTED from PRD): (1) Plugin = install/hook glue + ships companion binary, no product logic; (2) Companion = long-lived TUI, transcript-watch for turn boundaries, websocket, chat UI, pane placement; (3) Backend = hub per Fork 1. v2 reconnect webapp deferred.
- (decision) Fork 2: Companion stack = Go + Bubble Tea (bubbles/lipgloss widgets, fsnotify for transcript watch, coder/websocket client). Single static binary, CI cross-compiles mac arm64/x64 + Linux + Windows. Prevents: shipping a language runtime, per-platform build divergence.
- (version) charmbracelet/bubbletea v1.3.10 (stable, actively maintained through 2026; v2 in dev). Web-checked 2026-09-01.
- (decision) Fork 3: Backend stack = Go (stdlib net/http + coder/websocket, goroutine-per-conn). Single repo (monorepo) with companion; shared Go module for the wire protocol -> zero client/server type drift. Static binary, FROM-scratch container. Prevents: protocol drift between spoke and hub, multi-language contributor split.
- (decision) Fork 4: Persistence = embedded SQLite (modernc.org/sqlite, pure-Go, no cgo), single file on a mounted volume. Holds: profile (pseudonym+blurb), block lists, cooldown rows (with expiry, ticker-swept), bans, account-key UUIDs, report payloads (brief). NOT persisted: live queue, active pairings, message content, rate-limit counters (in-memory only). Cooldowns persist as rows so a redeploy doesn't wipe small-pool-repeat protection. Prevents: a second datastore container, cross-restart loss of enforcement state.
- (decision) Fork 5: Public instance hosted on Fly.io (shared-cpu-1x + 1GB volume for SQLite + IPv4, ~$7-10/mo, WSS-native, auto TLS, fly deploy from the Dockerfile). Shipped self-host artifact = Dockerfile + docker-compose.yml (same image). Deploy paths differ (fly.toml vs compose) but consume one image. Not serverless (long-lived WS + local SQLite).
- (version) Fly.io pricing web-checked 2026-09-01: shared-cpu-1x 256MB ~$2/mo, volume $0.15/GB-mo, dedicated IPv4 $2/mo; minimal app ~$7-10/mo. Free tier discontinued 2026.
- (decision) Wire protocol: versioned JSON over a single websocket; message types defined in the shared /proto Go module (imported by both companion and backend). Prevents client/server schema drift.
- (decision) Unified exit: every chat-ending event is delivered as ONE identical session_ended message on the wire - no peer_left/blocked/timeout variants. Binds: protocol + both units. Prevents: a client revealing which exit occurred, violating PRD FR19 no-rejection rule.
- (decision) Protocol versioning: companion and backend negotiate protocol version on connect; backend supports current + previous minor. Prevents: a stale plugin-bundled companion breaking against a newly deployed backend (decoupled update cadences).
- (decision) Think-time authority: the companion alone decides busy-vs-back, by watching the Claude Code session transcript file. Plugin and backend never make that determination. Prevents: three components with three notions of when a chat should end.
- (decision) Plugin->companion boundary: SessionStart hook spawns the companion process with args = transcript path, config-dir path, server URL. No required IPC after launch (companion is authoritative via transcript watch). Prevents: hook-timing limits (30s cap / Stop-too-late) becoming load-bearing.
- (decision) Profile ownership: edited in the companion, pushed to backend on change; backend's stored copy is canonical and is what peers receive on match. Local copy is a draft/cache. Prevents: two profile sources of truth.
- (decision) Backend concurrency: a single goroutine owns all queue + pairing state, mutated only via a channel it consumes. All other connection goroutines send it messages. Prevents: FIFO-ordering races and double-matching a waiter.
- (decision) Data-at-rest rule: message content is never written to disk or logs. Sole exception: a report-payload row in SQLite (last N messages of that one chat), retained only until actioned. Binds: backend. Prevents: any persistence path that violates PRD FR15/NFR1.
- (decision) Admin surface: ban / list-reports / etc. are subcommands of the backend binary operating on the same SQLite file. No admin HTTP endpoint in v1. Optional REPORT_WEBHOOK env var notifies the maintainer on a new report. Prevents: an authn-bearing web admin surface (and its attack surface) in v1.
- (decision) Config mechanism: environment variables only, no config files. Companion: SERVER_URL (defaults to the public instance). Backend: PORT, DB_PATH, KEYWORDS_PATH, optional REPORT_WEBHOOK. Prevents: config-file vs env drift across the public instance and self-host deploys.
- (decision) Repo shape (seed): monorepo - /plugin (hook glue + bundled binary ref), /companion (Go TUI), /backend (Go hub), /proto (shared Go module: wire types). CI cross-builds companion binaries (mac arm64/x64, Linux, Windows), publishes the backend container image, attaches binaries to GitHub releases; the plugin pins a companion binary version.
- (decision) Status/observability: backend exposes GET /status (concurrent users, median time-to-match, reports outstanding, error rate - PRD NFR15). Structured logs to stdout (Fly captures). No message content in logs, ever.
- (decision) Account key (ADOPTED from PRD): random UUID at a stable OS-config path outside the plugin dir; companion reads/creates it and presents it; backend treats it as identity with no verification. Survives plugin reinstall; motivated evasion accepted.
- (direction) Deferred (named, not designed): v2 reconnect webapp + its datastore, pull-in matching, interest tags, multi-instance/horizontal scale, self-hosted pool federation, exact transcript-parse edge cases (interrupts/SubagentStop), rate-limit numeric values, keyword-list contents.

- (decision) AD-8 tightened: the single-writer goroutine loads all blocks/cooldowns/bans from SQLite at startup and is the sole in-memory reader/writer of policy state; SQLite is a write-through durable mirror. No other code path reads policy for a matching decision. Also owns pairing teardown. Closes: policy-lost-on-restart (blocks/cooldowns not honored) + split read/write paths.
- (decision) AD-8 FR9 algorithm pinned: scan from queue head; pair head with the first eligible successor (not blocked/cooldown/banned/self); if none in a bounded scan, head keeps waiting. Prevents starvation ambiguity + queue stall.
- (decision) New AD-14 (fail-open): a plugin hook and companion launch must never block, delay, or error the Claude Code session. Hook spawns detached with a hard timeout; any failure (spawn, missing binary, unreachable backend) is swallowed and CC proceeds. Binds plugin+companion. From PRD FR6 x2 / NFR6 / NFR8.
- (decision) New AD-15 (content sanitization ownership): the BACKEND is the single point that strips/inerts links, enforces message length caps, and rejects oversized/binary frames on ingest, before relay or keyword filter. The COMPANION never renders remote markup/control sequences (treats peer text as literal). Neither assumes the other does it. From PRD FR14 / NFR11, addendum safety keystone.
- (decision) New AD-16 (queue membership + one connection per key): the BACKEND owns all queue membership. The companion only reports ready/busy (derived from transcript, AD-6); the backend translates that to enqueue/dequeue and owns the FR20 silent-requeue. Exactly one active connection per account key: a second connect takes over, the prior connection gets session_ended + close (a person watches one session at a time). Closes: double-enqueue, key matched to two peers, FR36 1-concurrent-session ambiguity, spinner-forever.
- (decision) New AD-17 (reconnect grace): on spoke disconnect the backend holds the pairing for a short grace window (~10s). Reconnect with the same (account key, session id) resumes it. Expiry -> session_ended to the peer, both requeued if still busy. Involuntary requeues and grace resumes do NOT count against the match-rate limit (AD-2). Closes: wifi-blip destroys pairing + burns cooldown; griefer inflating a victim's rate limit via forced requeues.
- (decision) AD-4 tightened: the backend mints exactly ONE session id at pairing and sends it in the 'matched' message on EVERY chat (not only persisted ones). session_ended never carries a session id or any cause field. The companion decides whether to offer 'copy session id' from its local persist state, never from message contents. On leave/burst-end the backend stops relaying immediately; already-received messages are delivered, later ones dropped; session_ended is the peer's last message. Closes: id-presence leaking exit cause; per-handler id minting breaking v2 reconnect; in-flight drain ambiguity.
- (decision) AD-3 tightened + /proto v1 message set enumerated. client->server: hello(protocol version, account key), ready, busy, chat_msg(client_msg_id, text), leave, block, report(last_n), profile_put(pseudonym, blurb; empty = clear), forget_me, note_put(text), heartbeat. server->client: queued, matched(session_id, peer pseudonym/blurb, opener TEXT), chat_msg(text), session_ended, blocklist, profile_ack, error(code,msg), please_update. chat_msg is NOT echoed to sender (companion renders its own outbound optimistically by client_msg_id). please_update is its own type, sent before close. Relay is per-pairing single-writer, receipt order preserved.
- (decision) AD-13 tightened: admin subcommands (backend ban/reports) write SQLite; the serve process re-reads bans on a short interval (~10s) and on SIGHUP; 'backend ban' sends SIGHUP via pidfile if present. 'Immediately' (FR40) = within that interval. SQLite opened WAL + busy_timeout for the two-process access. Still no admin HTTP surface.
- (decision) New AD-18 (schema migration): the backend embeds ordered, forward-only SQL migrations and applies pending ones on startup against the long-lived volume DB; a schema_version row gates them; no down-migrations in v1. Parallels the wire-versioning discipline (AD-5) for data at rest.
- (decision) AD-2 carve-out (age gate): 'policy' AD-2 binds = matching + moderation decisions. The first-run 18+/safety gate (PRD UJ-5, FR43-44) is a LOCAL precondition in the companion with no server round-trip and no server-side attestation row - the companion simply won't connect until it's cleared. Consistent with 'nothing sent to the server until first-run screen done'.
- (decision) AD-8 cooldown timing: a cooldown row is written only after a pairing has lasted ~1 minute or exchanged >=1 message each way - not at pairing time - matching PRD FR34 intent. No cooldown for a pairing torn down inside the grace window with no exchange (phantom pairing).
- (decision) Empty-queue note (folds under AD-16/AD-10): the backend holds pending notes in memory only (short FIFO, per-pool), never persisted; a note is consumed by the next arrival (delivered as their opener text) or expires after a few minutes.
- (decision) Companion binary delivery: cross-built binaries committed under plugin/bin/<os>-<arch>/ in the plugin repo (git/GitHub marketplace distribution; Claude Code only, so the claude.ai top-level bin/ restriction doesn't apply). SessionStart hook resolves the binary via ${CLAUDE_PLUGIN_ROOT}. The plugin release pins one companion version. Accepts modest repo growth over a download-on-first-run step (which AD-14 fail-open would have to tolerate anyway).

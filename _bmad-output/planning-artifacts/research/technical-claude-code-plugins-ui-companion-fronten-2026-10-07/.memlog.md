- (claim) ref=1 status=verified class=feature-identity pub=2026-10 — Claude Code's native in-session interactive-UI mechanism for plugins is called 'mods', shipped v2.1.287 (~Oct 1 2026), labeled early-access/API-unstable by Anthropic's own repo README.
- (claim) ref=2 status=verified class=lifecycle-model pub=2026-10 — A mod's hooks module runs for the life of the session (not torn down between turns); $.clock.every/$.clock.after let it do background work and update the UI ($.ui.status/toast/log) independent of a conversational turn.
- (claim) ref=3 status=verified class=api-surface pub=2026-10 — No native websocket/persistent-socket API is documented for mods; the only networking primitives are one-shot $.http.fetch and $.mcp.call/connect. Confirmed independently by 3 of 4 round-1 assistants.
- (claim) ref=4 status=verified class=permission-model pub=2026-10 — Mods are explicitly NOT sandboxed; a mod runs with the full permissions of the user running Claude Code, including a spawned process running outside Claude Code's own sandbox feature. Confirmed independently by all 4 round-1 assistants.
- (claim) ref=5 status=verified class=cross-platform pub=2026-10 — Mod UI rendering only works in the CLI terminal and the Desktop app's Code tab; it does NOT render in VS Code extension chat panel, claude -p, Agent SDK, cloud sessions, or Remote Control viewers (desktop/iOS) of a session — confirmed as live open bugs on anthropics/claude-code within days of launch (#99045, #99217, #99401).
- (claim) ref=6 status=unverified class=operational-constraint pub=2026-10 — Whether $.process.spawn can host a genuinely long-lived child process (e.g. a websocket client) that pushes async events back into the mod/UI (vs. only polling via $.clock.every) is undocumented in round-1 sources; this is the single most decision-critical open question and needs a targeted round-2 follow-up.
- (source) Integration r2 (targeted follow-up): 6 sources (mods reference/api/events docs, canonical claude-code.d.ts fetched+grepped directly, gradually.ai changelog aggregator, sleeyax/paseo-plugins issue #111). - (claim) ref=6 status=disputed class=process-spawn-semantics pub=2026-10 — $.process.spawn is documented as an async-generator hook (same category as streaming turn.step), no timeout in the limits table (unlike process.run's 30s/10min), suggesting push-based delivery of a long-lived child's stdout — but the canonical claude-code.d.ts on GitHub main has NO process.spawn entry at all (only process.run), a gap the docs attribute to the type file lagging behind shipped versions. Net: plausible push-based background I/O, not confirmed with certainty; the companion's live-websocket-relay architecture is NOT ruled out by mods' no-websocket limitation, but neither is it proven to work as designed.

- (decision) Facilitator stance. Technique order: 1) Random Stimulation, 2) an invented technique, 3) Assumption Reversal (coach's pick)
- (technique) started Random Stimulation
- (idea) Themed chatrooms / rooms organized by shared interest or topic, instead of only 1:1
- (question) Matching: truly random vs algorithmic (proximity, interests, gender)?
- (insight) Target user: AI-pilled Claude users starved of human connection; anyone will do, but many would prefer an opposite-gender match
- (insight) Analogy: HelloTalk — a language-exchange app that half-turned into a dating app; risk/opportunity of same drift here
- (idea) Proximity-based matching (match people geographically near each other)
- (insight) Claude think-time can be very short, so FIFO queue beats any matching algorithm; also the lowest-hanging-fruit MVP
- (idea) MVP = pure FIFO pairing, no matching algorithm at all
- (idea) Companion webapp 'half' where each ephemeral chat has a shareable session ID
- (idea) 'Missed connections' board: you can't DM anyone, but you can post your session ID; the other person searches it, finds your contact info, and a built-in flow lets you actually connect
- (technique) started invented technique 'Two Clocks Ticking'
- (note) Invented technique 'Two Clocks Ticking': every encounter runs on two invisible countdowns (your Claude, their Claude), unseen and able to fire any moment; for each idea ask what it does when a clock fires mid-sentence; generate mechanics/etiquette/UI/emotional-design that exploit or soften the two-random-clocks structure
- (idea) Default (persist OFF): when your Claude finishes, the chat just ends and you forget about them — clean, no decision
- (idea) Persist ON: chat keeps going after think-time; you keep chatting until you choose to stop, anytime
- (idea) Plausible-deniability exit: leaving anytime is framed as 'my Claude came back', so bailing never reads as rejection
- (idea) 'Persist' is a user setting that can be defaulted ON
- (idea) On disconnect: just show the 'searching' spinner again and silently re-enter the queue — no 'they left' message
- (direction) Resist feature bloat / minigames — 'does your downtime distractor need another minigame?' Keep it minimal
- (idea) Fill dead beats with lightweight tooltips/nudges, e.g. 'why not edit your profile'
- (idea) Open each match with an auto-generated icebreaker prompt built from both profiles
- (insight) Per-match generated icebreakers may be too slow/costly to compute at match time
- (idea) Fallback: instant rotation of generic pre-written opener prompts
- (technique) started Assumption Reversal
- (idea) Active (non-waiting) users can be pulled into a match if they fit the searcher's target profile — opt-in match criteria to key off of
- (idea) Profile fields like a/s/l (age/sex/location) as match keys
- (insight) Adding a/s/l + targeted search makes it explicitly a pseudo dating app — recurring gravitational pull of the concept
- (insight) Reject the 'micro-consult / work help' direction: needs too much personal + context info, real human-help needs are highly domain-specific — 'everything breaks'. Keep the product as light social connection.
- (decision) Product stays scoped to lightweight serendipitous social chat, not a help/expertise marketplace
- (idea) Optional interest hashtags/tags in profile that lightly bias matching toward people sharing a tag, so you re-meet a small cast occasionally
- (insight) Risk of recurring matches: running into a creep tied to an interest would make you feel forced to drop that interest to escape them — need a per-person block that doesn't cost you the tag
- (decision) Framing: a for-fun, open-source plugin integrated with Claude. Not a startup.
- (decision) Keep FIFO core but allow opt-in 'pull-in': an active (non-waiting) user can be matched if their profile matches what a searcher is looking for
- (decision) Accept a light dating-match element rather than fighting the concept's pull toward it
- (insight) Chosen direction: for-fun OSS Claude plugin; FIFO baseline + optional profile-matched pull-in; light dating-match OK; ephemeral-by-default chat with persist toggle; companion webapp with session IDs + missed-connections board as v2
- (idea) Pull-in small-pool repeat problem needs careful design: e.g. rate-limit re-matches with the same person — ~1 minute together, then auto-block them for a day (temporary cooldown) to force variety
- (direction) Open design question flagged for downstream: anti-repeat / cooldown rules for pull-in and small pools
